# M1 品牌与去耦规则

## T1.2 数据目录与环境变量

- CLI/adapters 配置边界负责解析路径，内部包名、协议和标识符保持不变。
- 默认数据根为 `~/.comecode`。`COMECODE_DATA_BASE_DIR` 优先于 `ZCODE_DATA_BASE_DIR`，两者都表示父目录（实际根为 `<base>/.comecode`）。空白路径按未设置处理；支持 `~` 展开。
- `COMECODE_X` 优先于对应 `ZCODE_X`，未设置才回退；显式空字符串保留，继续遵循原变量的解析规则。入口映射到内部旧键，adapter 直接调用同样兼容新键。
- `COMECODE_STORAGE_DIR` / `ZCODE_STORAGE_DIR` 保留原语义，仅覆盖 CLI 存储根，不改变 Provider 的 v2 配置根。用户配置仍为 `<dataRoot>/cli/config.json`。
- 首次运行发现旧根存在、新根不存在时，交互终端询问是否导入，默认否；非交互仅提示。确认后复制，旧数据不删除，新根已存在或显式指定数据目录时不提示。失败向入口传播，不静默忽略。
- Provider、会话、日志、调试轨迹、凭据、设备状态、运行工具与图片/执行缓存默认写入新根。项目 `.zcode` 配置与插件 manifest 仍兼容，不改变项目协议。
- 验收：前缀优先/回退/空字符串与路径展开单测；导入同意/拒绝/非交互场景；隔离根启动不创建 `.zcode`。

## T1.3 去掉强制登录

- 独立 CLI/TUI 只依赖用户配置的 API Key Provider，不因缺少厂商账号而进入登录流程；保留内部账号协议供其他宿主使用。
- 没有可用模型时提示配置 `<dataRoot>/v2/provider_config.json`；标准环境变量自动生成 Provider 属于 T2.2，本任务支持现有配置路径环境变量。
- 对外帮助与 TUI 命令列表隐藏 login；显式旧登录命令返回配置引导。logout 可用于清理历史凭据。
- 验收：无厂商凭据、配置 API Key Provider 的完整无头会话；无 Provider 返回配置指引。

## T1.4 默认关闭外连

- 独立 CLI 的官方 Coding Plan 网关不改写用户模型地址，也不初始化厂商账号/刷新凭据。
- Provider 目录只读随包 JSON（显式本地配置路径优先），不使用旧 CDN 缓存或远程刷新。
- 默认插件市场关闭；通过现有 `plugins.extraKnownMarketplaces` 显式配置才启用对应市场。本地插件、随包资源和用户显式配置的 MCP 不受影响。
- 未配置 OTLP 时不上报遥测，配置 OTLP 表示用户主动启用。
- 验收：mock HTTP 的完整会话仅请求用户模型白名单主机，覆盖网关、Provider 目录、市场以及未设置 OTLP 的情况。

启动事件顺序：CLI 环境映射 → 导入确认（可选）→ 本地 Provider 路径准备 → Registry 加载 → 模型请求（用户配置地址）。Registry 是 Provider 快照唯一所有者，adapter 只执行 I/O；没有新增远端状态或重试路径。
