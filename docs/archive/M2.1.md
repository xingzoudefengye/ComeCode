# M2.1 统一 Provider 配置系统

## 目标

在保持现有 `provider_config.json`、`@zcode/*` 包名、Provider Registry 与内部协议兼容的前提下，为独立 CLI 增加统一 Provider 配置入口。

## 配置来源与优先级

从低到高依次为：

1. 内置默认与现有 `provider_config.json`；
2. 用户配置 `~/.comecode/config.toml`；
3. 当前项目配置 `.comecode/config.toml`；
4. 标准环境变量：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`GEMINI_API_KEY`、`COMECODE_MODEL`，并兼容 `MODEL`；
5. CLI `--model` 与 `--provider`。

`COMECODE_*` 环境变量遵循已有 M1 兼容规则；本任务中的标准变量不改写为 `ZCODE_*`。

## 文件格式

支持 README 中的最小格式：

```toml
model = "deepseek-v4.1"
provider = "newapi"

[providers.newapi]
type = "openai-chat"
base_url = "https://example.test/v1"
api_key_env = "NEWAPI_API_KEY"
```

支持的 type 映射：

- `openai-chat` → `openai-chat-completions`
- `openai-responses` → `openai-responses`
- `anthropic` → `anthropic-messages`
- `gemini` 只识别和检查，不生成当前执行链可用的 Provider。

M2.1 只实现配置所需的 TOML 子集，不实现导入器、Gemini 原生请求或 Web 管理后台。

## CLI 命令

- `comecode config path`：输出用户配置路径、项目配置路径和实际存在状态。
- `comecode config show`：输出合并后的有效配置；API Key 及其环境变量值必须脱敏。
- `comecode config check`：校验文件、Provider type、必需字段和密钥来源；Gemini 配置仅报告“暂不支持原生执行”，不作为可执行 Provider。

## 验收场景

- 用户配置存在时，项目配置只覆盖同名字段，项目 Provider 可新增。
- 标准环境变量可在没有 TOML 的情况下生成 OpenAI、Anthropic 或 Gemini 配置；`COMECODE_MODEL` 优先于 `MODEL`。
- `--model` 和 `--provider` 覆盖配置文件与环境变量对应值。
- 统一配置 materialize 后仍由现有 Provider Registry 读取 `provider_config.json`。
- `config show` 不输出明文 API Key，`config check` 对缺失密钥、非法 URL、未知 type 返回非零结果。
- 没有统一配置来源时保留 M1 原有 provider setup 行为。

## JSON / JSONC 多模型配置（2026-10-01）

- 推荐公开配置为 `~/.comecode/config.json`；支持带注释与尾逗号的 `config.jsonc`，保留 TOML 和旧 v2 JSON。
- 每个目录只选择一个文件，顺序 JSON > JSONC > TOML；多个文件存在时报告被忽略文件。项目向上查找最近含配置的目录，再按格式顺序选择。无配置时直接交互填写并创建 JSON；首次引导不展示路径/格式，不创建多格式模板。显式 config setup 保持已有空模板格式，已有有效文件不自动迁移。
- JSON 顶层为 model/provider/providers；providers 为带 id 的数组。models 支持字符串或对象（id/name/type/baseUrl/apiKey/apiKeyEnv/contextWindow/maxOutputTokens/toolCalling/vision）。供应商支持 name、连接字段以及同名能力默认值，模型覆盖供应商默认。
- 用户与项目按供应商 id、模型 id 合并。模型数组显式声明成员集合，项目列出的模型继承同 id 用户模型字段，未列出模型不再作为公开配置成员。CLI/环境显式模型允许新增成员。
- 数值必须正整数，布尔值严格校验；未知字段、重复 id、无效 URL/协议返回错误。JSON 语法错误只报告文件和类别，不回显可能含密钥的源文本；show 对所有模型凭据脱敏。
- adapter 统一解析器为配置唯一所有者：文件 → 合并 → 环境/CLI覆盖 → 兼容 materialize → Registry → 模型工厂。Registry 保持供应商/模型原标识；Provider 增加可选模型连接与显示名覆盖，resolver 用有效模型协议匹配内置规则，bootstrap 用同一冻结连接执行。
- 能力写入现有模型规则，显式 contextWindow 不改成默认；maxOutputTokens 为支持上限，非固定请求预算。Gemini 模型只识别/检查，不进入执行成员；显式选择它必须拒绝，不回退其他模型。
- materialize 按标识更新托管规则并清理该供应商过期模型规则；不修改非托管旧规则。坏配置不写入运行时文件、不静默启动旧模型。
- 新会话默认模型仅缺少 reasoningLevel 时在 bootstrap 初始化边界补齐，恢复语义不变；不得回退第一个模型。
- 向导发现已有有效配置时拒绝整体替换，指引直接编辑添加模型，防止丢失高级配置。空模板仍可完成原向导流程；原文件替换需确认并备份。
- 验收覆盖格式与路径优先、项目合并、环境/CLI、脱敏和坏配置、旧 codec/Registry、真实 bundle 请求不同协议与正确模型、能力/窗口、向导高级配置保留。

### 首次使用补充

- 真实 TUI 入口在启动渲染及 Provider runtime 前检查配置；交互终端无可用模型且没有非法配置时直接运行向导，不让用户退出再执行命令。
- 只收集接口类型（回车默认 OpenAI Chat）、接口地址（默认官方地址）、实际模型名与密钥，其他使用既有默认。不展示保存路径/格式、不询问保存确认；填写后自动保存用户 config.json，再走同一 runtime 初始化继续启动。
- 已有有效配置不覆盖；遇到坏配置报告错误，不用首次流程掩盖。非交互、help、headless、协议入口不提问；Ctrl+C 中止且不写入。Web 多模型管理本次不实现。
