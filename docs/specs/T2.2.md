# T2.2 标准环境变量零配置启动

## 范围与所有者

复用 adapters 的统一配置解析器作为唯一配置所有者；CLI 入口在 Registry 启动前 materialize，并仅在 stderr 输出一次选择说明。不改 Provider Registry、内部协议、contextWindow 或 M1 默认外连策略。

启动顺序：环境归一化 → TOML/旧 JSON 读取 → 标准环境变量与 CLI 合并 → materialize → stderr 说明 → Registry → 模型请求。

## 规则

- 统一配置模型的图片输入能力缺失时默认支持，materialize 明确写入 `supportsImage: true`，不继承目录里的禁用兜底；显式 `vision: false` 仍禁用。管理页显示“支持（默认）”，不再使用含糊的“使用默认值”。

- 没有用户/项目 TOML 时，探测有非空凭据的 Provider，顺序为 OpenAI → Anthropic → Gemini；只有 BASE_URL 不视为可用凭据。
- `--provider` > `COMECODE_PROVIDER` > TOML 中的 provider > 环境自动探测（仅无 TOML）> 旧 JSON 默认。不额外增加 `ZCODE_PROVIDER` 回退。
- `--model` > `COMECODE_MODEL` > `MODEL` > TOML model；没有 TOML 的环境 Provider 在缺少模型时使用固定默认，不沿用其他 Provider 的旧默认模型。
- 固定默认模型：OpenAI `gpt-4.1-mini`、Anthropic `claude-sonnet-4-5`、Gemini `gemini-2.5-flash`。这不是“最新模型”跟踪机制；自定义网关必须自行确认模型支持，必要时设置 COMECODE_MODEL/MODEL。
- OpenAI 环境变量继续使用 openai-chat 协议（官方地址也允许 chat），避免改变 M2.1 的既有 API 映射。
- Anthropic API Key 优先于 AUTH_TOKEN，后者仅作回退。
- 同时存在多个凭据时，各环境 Provider 都有默认模型；选中模型（包括 CLI 覆盖）必须加入该 Provider 的模型列表。
- 有 TOML 时保留 M2.1 的同名字段合并语义；环境自动探测不覆盖 TOML 明确选择。
- 启动提示只含 Provider ID、模型 ID和选择来源，不含密钥或 endpoint；对控制字符转义，避免终端注入。config/help/version/logout 等非模型命令不输出提示、不 materialize。
- COMECODE_PROVIDER 指向不存在或不可执行的 Provider 时，在 CLI 入口报错，不静默选择其他模型。环境自动选择 Gemini 时明确提示暂不支持执行；不实现 Gemini 原生调用。
- 复用现有 JSON materialize 兼容格式，不改 Registry 或用户配置方式。用户级模型/Key 配一次供所有项目复用，不新增逐项目信任、授权或确认。
- 有效配置隔离（T2.6）：用户统一配置与 legacy `provider_config.json` 是输入来源；CLI 启动只把合并结果写入独立运行时快照，不能写回 legacy 来源（包括显式环境路径）及其托管记录。每次启动使用唯一快照，项目 A、B 或同项目并发启动互不覆盖；项目、环境和 CLI 覆盖只影响当前快照。
- materialize 在来源和目标分离时，从 legacy 来源继承未托管规则、手动能力与默认选择，而非从此前运行时快照继承。无统一配置来源时仍将 legacy 兼容配置复制到快照供 Registry 读取；解析或选择失败不得修改来源或允许 Registry 回退使用旧快照。
- 长驻协议进程（app-server/agent-server）的运行时快照跟随统一配置重新投影：桌面/Web/CLI 新增或停用模型后，同进程无需重启即可解析；连接测试等要求配置确定性的协议请求先按需投影再刷新 Registry。一次性命令仍保持每次启动唯一快照。

```text
用户统一配置 + 用户 legacy（只读） + 项目/环境/CLI 覆盖
  → adapters 唯一解析器 → 本次启动独立 JSON 快照 → Registry
                         不回写来源，不共享可变快照
```

## 验收

- 无 TOML，分别仅设置 OpenAI/Anthropic key（或 auth token）能得到默认模型。
- 多凭据选择顺序、COMECODE_PROVIDER、CLI 覆盖、空白变量、仅 BASE_URL、旧 JSON 默认与 TOML 兼容。
- 启动提示写 stderr 且不泄露密钥；config/help 等只读命令无提示与写盘。
- Gemini 和无效显式 Provider 不启动模型请求。
- 隔离临时数据根，用真实 CLI 入口准备、run/Registry/App + HTTP mock 验证环境变量启动得到响应；仅允许用户模型主机，检查模型与鉴权。
- 长驻协议进程运行中修改统一配置新增模型：文件监听路径与按需投影路径都必须让 Registry 在同一进程内解析到新模型。
- 相关 typecheck、oxlint、全量 CLI 测试、comecode --help 冒烟。
- 临时 A/B 项目共享虚构全局模型与 Key：A 的项目覆盖和 CLI/环境覆盖不得影响 B 或全局；本地 HTTP mock 验证快照中的模型、地址与鉴权。并发启动快照唯一，缺凭据失败不回写来源，显式 legacy 路径和原手动能力兼容，用户托管侧车保持不变。
- 快照使用系统临时目录，文件权限保持 `0600`，正常进程退出清理；强制终止可能留下临时文件，但下次启动绝不读取复用。无 legacy/统一来源时不生成空 JSON，保留 Registry 的旧 CLI 配置迁移路径。

## 供应商独立启停（adapters 配置边界）

- 全局 `config.json` 是供应商与模型开关、Key 和能力的事实源；editor 仅通过现有版本校验/原子保存路径修改它。解析与 materialize 只生成当前运行时投影，不回写全局文件或 legacy 输入。
- JSON/JSONC 的 provider `enabled` 与 TOML Provider 表的 `enabled` 仅接受布尔值，缺失等同 `true`；模型 `enabled` 独立保留。供应商 `false` 时全部模型不可执行，不改变模型自身开关、独立凭据、继承凭据或能力；重新启用时只恢复原本启用且连接合法的模型。
- 停用供应商允许保留未就绪连接；字段类型、重复 ID 和互斥 Key 来源仍校验。无模型的供应商可合法保存（连接字段可缺失），但不是执行候选，不产生凭空模型。
- 配置默认指向停用供应商、停用模型或空供应商时，优先同供应商合法模型，再回退其他可执行供应商；无候选则清除运行时默认，editor 保存同步修正默认。CLI/环境显式指定停用供应商或停用模型时拒绝，不静默回退。
- materialize 排除停用供应商的 Provider 执行规则，并对其所有模型生成停用投影以覆盖旧目录/手动规则；保留能力叶子。投影中的停用状态不得污染事实源中模型独立开关。
- 验收仅使用临时虚构配置/本地 mock：schema 类型失败、缺失兼容、editor 预览不落盘/脱敏/密钥保留、启停往返、默认回退与显式拒绝、空供应商保存、旧规则排除以及输入文件字节不变。
