# 后台资源与子代理负载治理

- 模型创建的后台 Bash 默认归属当前回合，回合终态时停止仍运行的临时任务（完成、失败、取消均清理）。显式 `background_scope: "session"` 用于用户要求保留的开发服务、持续监控等，跨回合保留，仍可 TaskStop/会话关闭清理；旧 registry 未记录 scope 的任务保持原行为。
- 不根据命令文本猜测是否应杀进程，不停止其他回合、会话或用户手动启动的进程。自动清理复用 TaskStop/ExecutionPort 取消和进程树终止，错误不覆盖原回合结果。
- 普通子代理模型请求使用现有进程级排队治理，主代理仍优先准入；同供应商不同型号共享并发桶，防止渠道限流。
- 子代理默认并发天花板最多 3，仍至少 1；近期连续 2 个首响应超过 30 秒的请求触发降档，按 epoch 仅降一次，同批迟到请求不重复降档。优先首 provider event 延迟，无流式统计时使用完整请求耗时；本地排队时长不计入。
- 渠道 429/过载继续使用既有降档和 Retry-After；慢响应时不累积成功升档，稳定快速成功按既有滞后逐档恢复。
- 使用本地 stub、假时钟验证，不调用付费模型；并发约束的是活跃模型请求，不宣称已限制所有排队 child 对象的数量。
