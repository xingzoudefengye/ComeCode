# M4.1–M4.4 本地模型管理页

## 范围

- 仅实现三种执行协议的配置管理：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。不新增 Gemini 原生执行；旧 Gemini 配置保持可识别且不允许执行。
- 网页提供供应商/模型增删改、默认选择、协议/地址/凭据继承、显示名/窗口/输出上限/工具及视觉能力。会话、记忆、日志按实际需要扩展；不建设多实例 Hub。
- 使用 `comecode admin` 独立打开配置管理（不启动模型）；TUI 同进程可用 `--web` 启用并自动打开浏览器，`--no-web` 显式禁用，`--web-port` 指定端口。后台默认不启动，避免新增未请求的监听端口；后续再决定默认启用策略。无头/协议/help 不启动后台。

## 所有者与边界

网页 → CLI 本地 HTTP 边界 → adapters 配置编辑仓库 → config.json → 现有统一解析 / materialize → Registry。

- 统一解析器是有效配置唯一来源。编辑仓库只处理用户配置文件，不编辑运行中的 Registry；网页不再提供外层“保存配置”按钮，模型和供应商各自保存后立即写入配置。
- 用户配置为可编辑来源，项目覆盖、环境/CLI 覆盖仅只读展示，不将合并后的环境密钥写回用户文件。
- adapters 提供读取、脱敏、乐观版本校验与备份后保存的公共接口。CLI 不另写一份解析器。
- 原 JSONC/TOML 保存到 JSON 前需用户明确确认迁移，原文件备份并保留；不静默丢失原始注释。含未知字段/非法结构的文件拒绝编辑写入。
- 版本摘要覆盖同目录 JSON/JSONC/TOML 三个文件；同一服务器写入串行，外部修改/第二页面旧版本保存返回 409，不覆盖。原始文件备份含密钥、权限 0600；写临时文件后 rename 生成 JSON。用户原密钥未修改时按供应商/模型来源保留，改名或迁移不要求重填；删除密钥必须显式操作。

## 配置易用性优先（2026-10-04）

- 用户级模型与 Key 配置一次，所有项目直接复用；切换工作区不要求重新填写凭据或逐项目信任授权。
- 不新增 Provider/MCP 的逐项目审批命令，不以本轮配置改造改变既有权限体验。
- 配置隔离只处理内部正确性：项目临时覆盖不应污染其他项目的有效配置。该能力仍待实现，不把未完成草稿作为已交付行为。

## HTTP 安全与生命周期

- 只监听 127.0.0.1，随机 32 字节 token。分享 URL 使用 fragment，不写 token 到 URL query/服务器日志；浏览器读取 token 后清理地址栏并仅存 sessionStorage。
- `/api/*` 全部校验 Bearer token（常量时间比较）；检查 Host 和 Origin，拒绝非同源 Origin/跨站请求/非 JSON 写入；限制请求体 256 KiB。
- 页面 CSP 禁止外部资源与 inline 脚本（nonce 或独立脚本）、不允许 framing，API/page 均 no-store、nosniff、no-referrer。
- 密钥不返回网页，表单只显示“已配置”；新增 Key 使用 password 输入，保存后清空；diagnostics 和异常不输出凭据/远端响应正文。
- `测试连接` 只由用户点击触发一次最小请求，不弹二次确认；测试可能消耗额度，超时 15 秒，返回成功/HTTP 状态，不回显正文或密钥。简化目标是本地结构合法即可保存，测试可选、失败不锁保存；当前代码仍要求新增/编辑测试通过，尚待实现调整，不能把本次文档清理当成功能已改。
- `admin` 进程等待 SIGINT/SIGTERM 后关闭监听。TUI return/failure 的 finally 关闭后台，连接不阻止退出；端口占用明确报错，不隐藏失败。

## 简化默认页面（2026-10-01）

- 页面默认直接展示扁平模型列表，不要求用户先理解 Provider；添加模型时只展示接口地址、API Key、协议（默认 Chat Completions 兼容）和模型名，能力与窗口放入“更多设置”。
- 空配置页面直接提供一个可填写服务。新服务 ID 自动生成，不要求用户填写。新模型名使用当前统一配置已有协议默认值；协议切换仅更新未手动修改的新默认模型，不改已有模型。
- 默认模型不是任意兼容平台都支持；更多设置明确允许填写平台实际模型名，错误提示必须指引展开更多设置。不得声称仅地址/Key 就能保证任何服务可运行。
- 相同请求地址的模型自动归类到同一 Provider；不同协议通过模型级覆盖保存。模型列表按 Provider 轻量分组，并提供“编辑供应商”入口，可修改供应商名称、地址、默认协议、环境变量和共享 Key。折叠仅控制展示，不丢弃未保存草稿/原字段；密钥不回显。


## 模型启用/停用（2026-10-01）

- 模型卡片提供可用键盘操作的启用/停用开关，旧配置及新模型未声明 `enabled` 时默认启用；停用卡片仍保留，可继续编辑、删除和重新启用。
- 模型级 `enabled: false` 由统一配置所有，网页开关变化后自动保存；不提供外层“保存配置”操作，不中断运行中的会话。
- 停用不删除模型、凭据或显式能力（尤其是 contextWindow）；后台重新加载仍展示停用项。JSON/JSONC 支持此字段；原 TOML 模型字符串保持默认启用，网页保存按既有规则确认迁移为 JSON。
- 默认模型下拉框排除停用项；停用默认模型时优先选择同一供应商的可执行模型，再选择其他供应商的可执行模型，全部停用时清空默认。
- 手动配置默认模型被停用时同样处理；显式 CLI/环境变量选择停用模型则拒绝执行，不静默回退。Gemini、缺少 Key 等既有校验行为保持不变。
- materialize 复用旧 Provider Config 的模型 `enabled` 规则，Registry 不发布停用模型；不引入新协议或第二份状态。停用再启用时保留原模型能力规则。
- 验收：旧模型默认启用、单模型停用、同名内置模型不能复活、全部停用、重新启用、密钥不丢失/不泄露、项目覆盖、显式选择拒绝、实际 Registry 候选过滤；浏览器覆盖点击/键盘开关、默认模型过滤及保存重载。

## 添加模型复用已有接口（2026-10-01）

- 已有供应商时，添加模型的“接口地址”提供原生下拉框，选项显示供应商名称与地址；仍提供“手动填写新地址”。没有已有地址时维持原输入框。编辑已有模型保持原流程。
- 选择已有供应商后填入接口地址与默认协议（协议仍可修改），Key 输入框显示“已配置，留空复用”，不把真实 Key 返回浏览器或填进 password 字段。共享密钥及环境变量来源由现有配置编辑仓库按供应商 ID 保留，新模型继承供应商连接。
- 切换供应商或改为手填时清除当前 Key 输入，避免把上一地址新输入的 Key 用到下一地址；手填已存在地址也按现有归类逻辑提示复用共享 Key。
- 没有共享 Key 的供应商只带入地址，不冒用它某个模型的独立 Key；此时提示用户填写。选中已有供应商后填写新 Key，只给新增模型做覆盖，不替换其他模型共用的 Key。
- 配置简化目标：填完即可保存，连接测试是可选诊断，不因断网、临时限流或服务故障阻止保存；取消不新增模型，不恢复外层“保存配置”按钮。当前测试通过门槛仍存在，代码变更另行验收。
- 验收：新增模型无需重复地址/Key、默认协议继承且可覆盖、手填新地址、切换时不串 Key、标准环境变量及旧 provider_config.json 密钥复用、仅模型级 Key 的供应商不被误用、已有供应商无共享 Key 的中文提示、独立模型 Key 不修改共享 Key、读取/保存响应不泄露明文密钥。

## 编辑模型跨分组凭据保留（2026-10-02）

- 同地址修改协议只设置模型协议覆盖，不新建供应商；地址修改继续按新地址归类。
- 编辑模型留空 Key 表示保留该模型原来的有效凭据（含独立 Key/环境变量），即使模型重命名或迁移到新的供应商。
- 浏览器仅提交一次性的 `apiKeyFrom: { provider, model }` 来源引用；原始凭据唯一由 adapters 编辑仓库恢复。引用不写入 JSON，不在网页回显明文密钥。
- 引用必须指向已存在模型；非法/失效引用返回 422。明确的新 Key、新环境变量或清除动作优先于引用。
- 保存时序：表单候选 → 来源引用 → 编辑仓库恢复凭据并校验结构/版本 → 落盘。连接测试独立且可选，不作为目标保存流程的前置步骤；当前代码的测试门槛待调整。
- 默认模型迁移/重命名更新对应选择；不改变其他模型协议或凭据。验证需覆盖真实网页“Grok 根地址改为 /v1、Anthropic 改兼容、Key 留空”以及前端候选到真实编辑仓库的集成路径。
