# 用户跨项目记忆

## 范围与所有者

Runtime 是上下文快照的唯一所有者；本地 managed chronicle 是用户历史的唯一持久化写入路径。默认 `memory.scope=project`，只有 `both` / `user` 启用用户记忆，且 `enabled=false` 或 `use=false` 均禁止加载和历史读取。桌面 `memoryEnabled` 控制运行时 enabled，关闭不会删除文件。

项目 `.ai/` 保留五类文件及正常 Read-before-Edit、Write/Edit 权限；统一存储预算、状态更新、分层整理及迁移事务见 [有限容量项目记忆](BOUNDED-PROJECT-MEMORY.md)。用户稳定背景位于同一 CLI storage root 的 `memories/user/`，仅加载 profile.md、preferences.md（各最多 2000 字符、快照含标题最多 4000 字符）；只保存明确的用户偏好，不保存项目事实、不提升指令优先级。普通工具不会自动获得用户目录写入许可。

## 时序与预算

新 turn admission → 异步读取最新本地记忆 → 重新组装有界快照并替换旧记忆 section → tool steps 使用同一快照。冷恢复和压缩边界同样从当前文件加载最新快照；不追加记忆更新消息、不持久化旧基线、不要求模型对照新旧版本。同步配置重建不读磁盘或网络。Runtime 是当前加载快照的唯一所有者，文件仍是长期记忆事实源。

默认记忆投影按完整 Markdown 条目确定性选择，双根总预算含说明、标题和来源为 4000 本地估算 token，另受字符硬上限限制。用户偏好和项目核心约束优先，各项目文件保留配额，完整条目去重并跳过明确完成的 Markdown 任务；超大条目不截断为歧义文字，提供按需读取来源。原文件容量不变，不删除历史、不新增模型摘要调用或 UI。估算预算不是 provider usage。

长期记忆的提取、更新、合并和存储策略保持原样；本次只改变默认加载容量和条目选择。显式关闭 enabled/use 或收窄 scope 下次快照刷新即撤掉对应内容，权限、模型、工具和规则更新正常生效。内容未变时确定性重建保持同一文本；内容改变时允许缓存前缀变化，最新有效记忆优先于缓存。不能据本地容量优化宣称已定位恢复开销根因或提高真实命中率。

用户史书 chronicle.json 由终态回合 managed 写入，自动合并衰减，最多 6000 字符；不随每轮注入，通过 ReadSessionContext 的可选 scope=user 本地按需读取。默认 scope=session 保持旧 schema 使用方式，user 仍要求有效 sessionId（当前会话即可）；查询失败返回受控结果，无付费摘要模型调用。

自动提取仅写固定白名单，双根事务提交，输入 16000 字符/累计输出 2000 token，最多 3 turn / 30 秒。稳定偏好不做时间模糊，但受容量限制。上述预算是固定常量，暂无配置入口。

## 后台模型用量

记忆提取每次实际 generateText 调用由 Runtime 写入现有 model_usage，querySource 为 project_memory_extract；每次调用生成独立 child span，继承原 session/turn/trace，避免多轮提取相互覆盖。记录有效模型/思考档位、输入、输出、推理、缓存读写、耗时、完成/失败/取消及请求内重试；没有 provider usage 时保持未知，不把内部字符预算当真实 token。

返回的 usage 在执行工具或检查提取预算之前记录，之后工具写入失败不抹掉已花费的调用。存储失败按现有 warn 策略处理，不阻断记忆或主对话；后台不注入主对话 ModelComplete，不污染上下文窗口或重复累计主 turn 用量。现有 model_usage 总量查询自然包含这些记录；本次不新增费用估算或 UI。

主流程与后台提取各自运行；本地交接压缩使用会话史书、当前任务和近期尾部，不等待提取、不调用额外摘要模型。统计不改变提取频率、权限或压缩行为。

## 批量触发与恢复

自动提取累计至少 3 条有效用户输入或 1500 字符触发，不用模型判断是否达到门槛；显式 /memory save 和恢复未完成批次绕过门槛。只取游标之后的有效用户文字，每批最多 6000 字符，旧工具、助手输出及注入指令不发给模型；积压按消息顺序推进，不因输入截断就把后续消息标成已处理。超长单条输入仍遵守既有有界投影，不保证全文记忆。

Runtime 的单个 scheduler 拥有进度，复用 SessionStore 的固定 runtime/memory_extraction entry 覆盖保存 cursor、pending boundary、根范围及失败退避时间；不复制原文、不建新表或常驻服务。每次调度先写 pending，再尝试提取；只有 success/no-op 或确定无有效输入时推进 cursor。失败/取消保留 pending，失败退避 60 秒，重复调度不重复提取已确认消息。旧会话没有进度记录时不在恢复首屏扫描提取全历史；首次新调度建立进度。已保存 cursor 或 pending 不在当前活动分支时，以当前边界重建基线并清除旧 pending，不回放旧历史；之后只处理新输入。根范围变更不自动将旧批次写到新范围。

恢复该会话后只异步补一批已记录 pending，不等待模型，不要求用户发送新消息；仍有积压则后续回合继续。自动提取禁用、无可执行模型或远程工作区不补跑。正常关闭先 shutdown 取消模型/清除内存 pending，随后只等待已有本地进度写入收口，不能启动退出提取；强杀不保证最后一次写入，但此前持久化的会话原文与 pending 可恢复。成功写文件后、进度确认前崩溃可能再次执行该批，需沿用内容去重与版本事务，不能承诺精确一次。

门槛和批量容量是内置默认值，本次不新增 UI 或配置入口；不改变交接式压缩，不恢复压缩前强制模型调用。已落盘会话历史及本地史书与长期记忆分离，跨会话长期记忆更新可能延迟。

## 兼容与验收

不迁移旧 hashed 目录，不加载旧 history.md，不跨设备或远端同步。没有新增 UI 管理承诺。测试使用临时配置与本地 mock，覆盖双项目共享 storage、禁用、默认 project、旧历史忽略、含标题预算和按需史书。损坏/缺失背景不阻断主流程；事务写失败不覆盖原文件。
