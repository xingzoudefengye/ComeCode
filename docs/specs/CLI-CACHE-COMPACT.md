# 请求缓存与自动压缩

## 产品规则

- 沿用现有预算配置优先级：显式 `compact.contextWindow` 可覆盖模型窗口；未覆盖时使用模型窗口，缺失或非法时回退到 512,000 token；内置目录的通用模型兜底同样为 512,000，模型专属规则和用户显式窗口不改写。
- 默认到窗口的 75% 自动压缩；合法的 `thresholdPercentOverride`（大于 0、不超过 100）优先。
- 实际阈值取百分比阈值与「窗口减输出预留、减安全余量」的较小值。压缩失败熔断、手动压缩和 microcompact 保持现有语义。
- 压缩会导致历史前缀重建；75% 是已确认的上下文策略，不能声称它本身一定省钱。不为达到缓存指标扩大模型窗口、填充无用上下文或跳过安全预算。
- 复用现有系统提示词稳定/动态分区和 Anthropic cache breakpoint，不新增重复断点，不重排历史消息或有因果关系的附件。
- 记忆按约 4000 本地估算 token 的完整条目投影加载（含双根说明/来源），不再默认注入 48000 字符历史。普通回合、冷恢复与压缩直接加载更新后的快照并替换旧 section，不追加更新记录或复用旧基线。内容未变保持确定性文本；记忆有变化时接受缓存失效，最新有效记忆优先。长期提取/更新/合并策略不变，本次不能证明恢复开销根因或真实命中率提升。
- 工具名称排序/schema canonicalization 保持原样，不冻结执行权限或能力，不改变会话缓存键；最终 SDK HTTP 请求比较首个差异位置和输入预算，本地验证不等于真实缓存命中率。
- adapter 发送工具时按名称的确定性顺序排列，JSON schema 对象键递归排序，数组顺序和校验语义不变；不修改注册表与调用方对象。
- OpenAI SDK 请求缺少显式 `openai.promptCacheKey` 时使用 `comecode:<sessionId>`；流式、非流式、重试、压缩请求共享同一会话键，子会话隔离。无会话身份则不补键，显式配置优先。
- 缓存亲和按协议发送：OpenAI Responses 使用 body `prompt_cache_key`，OpenAI Chat 兼容使用对应 Provider 的 body `prompt_cache_key`，Anthropic 使用 `metadata.user_id` 并沿用 `cache_control`。不把一种协议的 body 字段注入其他协议；请求体亲和字段不等于上游一定支持缓存。
- 随归一化会话身份补发 Codex CLI 标准 header `session-id` / `thread-id`，保留现有归因头；无会话时不发送，子会话隔离。Codex/Plus 兼容后端可能读取 header 做缓存亲和，仅检查 body key 或中转渠道数量不能排除客户端问题。标准头改动已提交为 `a489da8`（2026-10-03），生产效果仍需重启后验收。
- SDK 统一 usage 为主要事实；当 raw usage 包含各厂商缓存字段时补齐缓存统计。不把未知用量当成命中，不重复计入总输入。部分 OpenAI 兼容 SDK 会剥离非标准字段，仅返回 `prompt_cache_hit_tokens` 的端点尚不能保证统计，后续需要专门的 wire 适配；本轮不声称已支持所有 DeepSeek 端点。
- TUI 展示 runtime 下发的实际压缩阈值和已有 provider 用量的缓存比例；不在 UI 复刻模型预算公式。
- 主请求 ModelComplete 的有效正整数 contextWindow 同步进入权威会话投影及 TUI；回合结果不能再用初始化/恢复的旧窗口覆盖它。title/compact/subagent/tool_internal 等辅助请求不得改写主窗口或阈值。旧主事件缺少 querySource 时兼容读取窗口，但不以缺失字段清除当前值。
- 旧事件缺少窗口或传入 0/负数/NaN/Infinity 时保留当前有效窗口，不在 TUI 强制写 512K。模型切换后由最新主请求纠正旧投影。
- CLI 单包 build 在打包前按 contracts → core 更新直接运行时构建产物，避免 src 已更新但 dist 仍保留 200K 的混合版本。复用各包 TypeScript 配置，不引入新依赖或改变包名。
- 关闭自动压缩后，主请求不下发压缩阈值，TUI 清除旧阈值；辅助请求不覆盖主请求预算。

## 交接式压缩

- `392fd0f` 将摘要生成改为本地短交接；本轮进一步去掉原文尾部回带，压缩后仅保留稳定前缀和有界交接，原始消息仍在本地会话记录中。
- 固定容量阶段小结已在本地实现：最近细、旧历史粗，容不下时继续丢弃，回答大概即可。普通续作不重带全部历史，不建设新的索引、向量库或专用归档框架。
- 用户不用手动整理上下文，不因压缩等待长篇总结；没有新用户消息的再次压缩必须沿用上次交接中的用户目标，去掉包装而不递归套用旧交接。近期约束保留来源，不能当作新的授权。

## 固定容量史书与交接实现（本轮工作区实现）

- 每个普通回合结束后，本地提取已有最终回复和用户目标中的短小结；记录回合结束状态，不把 success 自动当作用户目标完成。成功、失败、取消都不触发额外摘要模型请求。
- 史书保存在已有 SessionStore 的单个 session entry，覆盖更新，序列化容量上限固定；近期小结较详细，早期记录合并为阶段、再合并为粗略代表事项，允许丢弃细节。它是历史背景，不是当前执行指令。
- 正常模型请求不附带史书；明确历史查询通过现有 ReadSessionContext 本地读取，不调用抽取模型。旧会话无史书时使用有界本地记录提取，损坏时降级，不阻断任务。
- 压缩只保留稳定前缀与有界文字交接：最新实际用户目标、近期进展、有限工具行动/结果及未完成状态。大工具输出与媒体不回带；工具调用和结果转为成对文字记录，不产生孤立协议消息。文件提醒只留路径，不重注入源码。
- 交接及提醒合计按固定上限与模型可用窗口取较小预算；稳定系统前缀自身不可压缩，不承诺其超过窗口时仍可执行。实时和冷恢复使用同一份持久化交接，不通过 preservedSegment 重载原始大尾部。
- 沿用取消、压缩失败与持久化边界；不伪造 ModelRequest/ModelComplete 或 usage。局部失败不删除原始消息，史书维护失败不阻断主任务。
- 验收覆盖万轮史书有界/近期优先、连续压缩/冷恢复、历史按需读取、失败取消状态、损坏降级、大工具入参/结果、零辅助模型调用和本地耗时；不读取真实用户数据库或调用付费服务。

## 95% 命中率目标与证据边界（2026-10-02）

- 指标采用服务商返回的缓存读取输入 token / 总输入 token，按 token 加权，不平均每次请求的百分比；缓存写入不计入读取命中。输出 token 不进入命中率分母。
- 大上下文且本轮增量较小的连续请求，以实际读取命中率至少 95% 为目标；短上下文、首次冷请求、缓存过期、切模型与压缩后的冷启动必须保留真实数值，不强制达到该比例。大上下文只是更容易使增量占比小，不能保证回答准确或服务商缓存命中。
- 全会话累计口径包含首次冷请求；若另行报告预热后命中率，必须同时报告含冷启动的累计值、样本请求数、输入 token、缓存读取和写入 token。当前 TUI 统计仅针对主会话，不得当作所有后台调用的整体指标。
- 未报告缓存用量的接口标为未知，不能把未知认作 95% 或 0%。禁止通过增大重复内容、额外付费预热/保活、修改返回 usage 或只选高命中样本达标。
- 真实诊断需同一足够长前缀连续多次采样，单一一次或两次 A/B 不能给出可靠稳态命中率。「出现缓存读取的请求数 / 请求数」与「缓存读取 token / 总输入 token」是不同指标，报告时不得互换。
- 本地回归使用真实 SDK 序列化和 mock fetch 捕获最终 JSON，覆盖 Responses、Chat Completions、Anthropic Messages 的流式与非流式缓存参数及历史稳定性。mock 返回 95% 用量样例只验证映射，不能证明服务商实际命中。
- 真实验收需要用户授权的 Provider、模型、请求样本和费用预算。未获得这些输入时只运行本地测试，不读取或发送用户历史和凭据。没有真实 usage 证据时，95% 目标状态为未验证。

## 所有者与顺序

```text
会话身份/消息历史（runtime） -> 请求投影（core） -> 稳定序列化（adapter） -> provider
预算配置 + 模型能力（runtime） -> compact policy -> 实际阈值事件 -> TUI
provider usage -> adapter 归一化 -> session 用量累计 -> TUI 缓存比例
```

## 验收

- 状态栏验证 16.2K/1M（2%）与 Compact 600K；默认窗口显示 512K；显式 32K/128K 保持原值。投影恢复、辅助请求、缺失和非法窗口回归覆盖。
- 编译产物与源码默认 512K/384K 一致；单包 CLI build 更新 contracts/core，未知模型的 Registry 兜底为 512K，deepseek-flash 的目录窗口仍为 1M。
- 缺少模型窗口时按 512K 计算，默认在 384K（75%）触发；边界前一 token 不触发；小窗口受输出预留保护。Provider 明确声明的模型窗口保持原值。
- 10 轮请求的稳定系统前缀、工具 wire 定义逐字一致；动态日期与新消息不改变稳定系统区。
- 工具排序、schema 键排序不改变原输入、枚举/数组次序、strict 和 provider native 的能力语义。
- 缓存键同会话稳定、子会话不同、显式选项不覆盖、不支持接口不注入。
- Anthropic/OpenAI/DeepSeek/Gemini 用量样例验证缓存字段；真实费用与服务端命中率须连接 provider 后确认。
