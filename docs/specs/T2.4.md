# T2.4 配置导入规则

## 范围

ComeCode 支持从 Codex 和 Claude Code 的本地配置中导入 Provider，不执行网络请求，不导入 Web 后台或 Gemini 原生协议。

## 命令

```text
comecode import codex
comecode import claude
comecode --import codex
comecode --import claude
```

默认目标为 `~/.comecode/config.json`。已有统一配置不会被整体覆盖；相同 Provider 和模型重复导入时跳过。

## Codex 来源

- `~/.codex/config.toml`
- `~/.codex/auth.json` 只用于判断是否存在 OAuth/认证信息，不读取 token 到输出，也不写入 ComeCode。
- 支持 `model`、`model_provider`、`[model_providers.<id>]` 的 `base_url`、`env_key`、`wire_api`。
- `wire_api = responses` 映射为 `openai-responses`，`wire_api = chat` 映射为 `openai-chat`。

## Claude 来源

- `~/.claude/settings.json` 的 `env` 对象。
- 读取 `ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL`、`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`。
- 协议固定映射为 `anthropic`。

## 安全与失败行为

- 终端摘要、JSON 摘要和错误信息都不能包含真实 API Key、OAuth token 或完整源文件。
- 写入前备份已有目标文件，临时文件写入完成后原子替换。
- 源文件不存在或格式错误时返回清晰中文错误，不创建空配置。
- 导入只写配置，不自动验证远端、不发送模型请求。
