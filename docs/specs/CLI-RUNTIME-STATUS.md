# CLI 运行状态与子代理监督

## 所有者与边界

- RuntimeTaskRegistry 是子代理生命周期的唯一所有者；TUI 只从事件和现有目录快照投影显示。
- 复用 Agent、TaskOutput、TaskStop、后台通知队列和现有取消信号，不新增登录、网络或环境变量。
- core 的改动限于子代理生命周期和取消接线；不改模型执行算法，不引入第二套任务调度器。
- 当前子代理是同进程异步会话。监督独立于模型决策，但仍依赖 Node 事件循环；同步堵塞的强制回收需要后续进程隔离。

## 监督与终态

1. 前台、显式后台、前台转后台及 SendMessage 恢复执行使用相同无活动监督，复用 `subagents.inactivityTimeoutMs`，默认 600,000ms。
2. 启动和会话准备也受监督；无活动期限可由现有配置调整。不用固定总时长限制持续有进展的长任务。
3. 等待权限、用户回答和工作区 hook 确认时暂停无活动计时，响应后重新计时。仅递增耗时的 progress 不算新进展。
4. 超时请求取消并解除主任务等待，即便 child Promise 忽略取消也要结算失败；不把等待超时当成执行超时。
5. 执行退出、收尾退出和仍在进行的投影分别记录。旧执行或写入未退出时拒绝恢复同一 child session，防止新旧运行重叠；投影等待期限为 5 秒，但等待结束不代表底层 I/O 已退出。
   SendMessage 恢复准备失败时保留旧终态；准备阶段的 metadata 写入如果仍未退出，也必须阻止再次恢复，直到该写入实际结束。
6. 取消信号立即封闭 child 后台通知、取消其后台命令，并阻止其迟到事件投影到父会话。
7. 用本轮 trace span 区分同一子代理的多次运行；终态仅提交一次，迟到结果不能覆盖终态或新轮状态。
8. 终态先写 registry。日志、输出产物和界面事件失败不使任务回到 running；失败产物写不出来时仍通知父会话并保留原错误。
9. 后台通知入队失败最多尝试三次；仅入队成功才设置 notified，重试前检查当前运行和已通知标记。终态不得因通知失败回滚。
10. 保留 Provider 原有有限重试。子代理整体涉及文件和命令副作用，不自动重跑整个任务；错误交回主代理接手或报告阻塞，其他任务继续。

```text
child 事件 -> 活动监督 -> 取消信号 -> registry 终态
                             |          |
                             |          +-> 父通知队列 -> 主代理继续
                             +-> child 后台命令回收
registry / session 事件 -> TUI 阶段、耗时、进展、后台数量、终态
```

## TUI

- 输入区下方使用固定高度状态行，显示模型等待、工具执行、重试、用户确认、压缩和结束状态。
- 显示本轮耗时、距最近真实进展的时间、后台任务数量；90 秒无新进展显示弱警告，不仅凭此自动杀任务。
- 用户确认期间不显示停滞警告。主会话结束仍有后台任务时显示“已完成”和子代理数量，目录与侧栏继续反映子代理状态。
- 单个子代理失败不将主会话标记成失败；由主会话终态事件决定本轮完成、失败或取消。
- 复用双语文案与主题语义色；窄终端截断显示，内容不得改变状态行尺寸。
- 保留已用/总上下文窗口，并展示运行时提供的自动压缩阈值；不从界面重复推断模型预算。

## 验收

- 前台与后台 child 永不返回、准备阶段永不 ready：期限后主调用解除，任务不残留 running。
- 前台转后台、恢复执行仍受监督；正常活动重置期限，确认等待暂停期限。
- 忽略取消、取消后迟到成功或失败：父任务继续，终态不被覆盖，旧执行未退出不能恢复。
- 子代理失败同时输出目录不可写、事件发送失败、通知首次失败：终态仍提交，通知有限重试，无未处理 Promise rejection。
- 一个子代理失败，另一个可正常完成；TaskOutput 等待超时不杀后台任务。
- TUI 覆盖等待模型、并行工具、确认、后台继续、完成/失败/取消；不同语言和终端宽度渲染不溢出。
